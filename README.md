# terraform-provider-klaviyo

Terraform provider for [Klaviyo](https://www.klaviyo.com).

## Source

This provider's source lives in the
[`aroma-zone/terraform-providers`](https://github.com/aroma-zone/terraform-providers)
private monorepo under `providers/klaviyo/`. Each release is mirrored to
this repo automatically; **do not open pull requests here**, open them
against the monorepo.

## Quick start

```hcl
terraform {
  required_providers {
    klaviyo = {
      source  = "aroma-zone/klaviyo"
      version = "~> 0.1"
    }
  }
}

provider "klaviyo" {
  # api_key reads from KLAVIYO_API_KEY env var if not set here.
}

resource "klaviyo_list" "newsletter" {
  name           = "Newsletter"
  opt_in_process = "single_opt_in"
}
```

## How this provider is built

Hand-written against Klaviyo's official
[OpenAPI specification](https://github.com/klaviyo/openapi). The pinned
spec lives in [`spec/openapi.json`](./spec/openapi.json) (stable) and
[`spec/openapi-beta.json`](./spec/openapi-beta.json) (beta — used by
`klaviyo_custom_object`). The provider sends `revision: 2026-04-15.pre`
which unlocks the beta surface without breaking stable endpoints.

We evaluated and rejected HashiCorp's `tfplugingen-openapi` because it
silently drops `allOf` compositions in the Klaviyo spec, and we ruled
out Speakeasy because Terraform generation is gated to a paid plan.

| | |
|---|---|
| Klaviyo API revision sent | `2026-04-15.pre` |
| Stable spec commit | [`796408b`](https://github.com/klaviyo/openapi/tree/796408bfb8bb1ea6f27d730ae548e492bfc0c5b0) |
| Beta spec commit | [`d47af7b`](https://github.com/klaviyo/openapi/tree/d47af7b4f83766d701a9091118ae14c278c1efb7) |
| Plugin Framework version | `v1.19.0` |
| Minimum Go version | `1.25` |

## Building locally

```sh
make build      # produce ./bin/terraform-provider-klaviyo
make test       # run unit tests
make tools docs # regenerate ./docs/ from the schema (tfplugindocs)
make fetch-spec # refresh spec/openapi*.json from the pinned upstream commits
make help       # list all targets
```

## Bumping the upstream spec

1. Edit [`spec/version.txt`](./spec/version.txt) (new revision + commit SHAs).
2. Run `make fetch-spec`.
3. Inspect the diff in `spec/openapi.json` / `spec/openapi-beta.json` for
   breaking changes.
4. Update the hand-written schema / CRUD where the API changed.
5. If the revision suffix changes, also bump `defaultAPIRevision` in
   [`internal/provider/provider.go`](./internal/provider/provider.go).
6. Tag a release (`klaviyo/vX.Y.Z`) from the monorepo to publish.
